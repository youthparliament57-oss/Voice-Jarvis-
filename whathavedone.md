**2. Android Manifest (`AndroidManifest.xml`)**

- Registered `JarvisService`.

**3. Secure Data Storage (`SettingsRepository.kt`)**
- Implemented `EncryptedSharedPreferences` with `MasterKey` (AES256_GCM).

**4. Progressive Permission Flow (`PermissionsHelper.kt` & `PermissionsScreen.kt`)**
- Created a specialized UI that blocks the user until they grant:

  - Display Over Other Apps (Overlay permission via `Settings.ACTION_MANAGE_OVERLAY_PERMISSION`)
  - Usage Access (Usage stats permission via `Settings.ACTION_USAGE_ACCESS_SETTINGS`)

**5. Settings UI (`SettingsScreen.kt`)**
- Built a secure input field with password masking to let the user save their Gemini API key. 
- Integrated with `SettingsViewModel`.

**6. App Navigation (`MainActivity.kt`)**

## ✅ Step 3: Foreground Service & Floating Overlay (Completed)

**1. The Floating Visualizer (`JarvisOverlay.kt`)**
- Built a Jetpack Compose UI component that pulsates with different colors based on `AssistantState` (IDLE, LISTENING, UNDERSTANDING, SPEAKING).

**2. The Background Engine (`JarvisService.kt`)**
- Implemented an Android `ForegroundService` that keeps the app alive in the background with a persistent notification ("JARVIS is awake").
- Interfaced directly with Android's `WindowManager` using `WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY`.
- Created custom `LifecycleOwner`, `ViewModelStoreOwner`, and `SavedStateRegistryOwner` logic to safely render the Jetpack Compose `JarvisOverlay` completely outside of an Activity (floating over the OS).

**3. Service Trigger (`MainActivity.kt`)**
- Added a button ("Start Background Service & Overlay") in the home screen to launch `JarvisService` using `startForegroundService()`.

## ✅ Step 4: The Wake Word Engine (Completed)

**1. TFLite Model Integration (`app/src/main/assets/hey_jarvis.tflite`)**
- Successfully researched and integrated an authentic "Hey Jarvis" Wake Word model from the open-source `microWakeWord` project.
- Exchanged the generic placeholder model with a targeted local model (`hey_jarvis.tflite`), ensuring offline operation.

**2. Audio Task Library Configuration (`build.gradle.kts` & `libs.versions.toml`)**
- Integrated `org.tensorflow:tensorflow-lite`, `tensorflow-lite-support`, and `tensorflow-lite-task-audio`.
- Modified Gradle cache manifests manually and excluded sub-modules to permanently resolve deep Android manifest namespace conflicts (`tensorflow-lite-api`) generated by version mismatches.
- Validated clean, error-free Gradle compilation.

**3. Wake Word Engine (`WakeWordEngine.kt`)**
- Created a custom detection engine utilizing `AudioClassifier.createFromFileAndOptions` and `TensorAudio`.
- Deployed an isolated background thread that securely passes continuous microphone buffers (`AudioRecord`) directly to the local edge model.
- Automatically calculates confidence scores natively without internet access, searching exclusively for the "Hey Jarvis" acoustic signature.
- Signals successful detection via Kotlin Coroutines `SharedFlow` (`wakeWordDetected`).

**4. Service Integration (`JarvisService.kt`)**
- Initialized `WakeWordEngine` within the strict `ForegroundService` lifecycle.
- Embedded a real-time listening Coroutine to monitor the `wakeWordDetected` stream.
- Implemented visual state transitions (LISTENING -> UNDERSTANDING -> SPEAKING) instantly updating the `JarvisOverlay` UI upon successful wake word validation.
